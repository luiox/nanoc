# NanoC 虚拟机指令设计文档

## 1. 指令集概述

### 1.1 设计目标
NanoC虚拟机指令集设计为32位栈式虚拟机指令集，支持基本的算术运算、逻辑运算、内存访问、控制流和函数调用。

### 1.2 指令分类
当前指令集包含27条指令，分为以下几类：
1. 内存访问指令
2. 算术运算指令
3. 逻辑运算指令
4. 比较指令
5. 栈操作指令
6. 控制流指令
7. 函数调用指令
8. 系统调用指令

## 3. 指令集完备性分析

### 3.1 现有指令集优点
1. **基本功能完整**：覆盖了算术、逻辑、比较、控制流等基本操作
2. **栈式设计**：适合函数调用和表达式求值
3. **寄存器设计**：8个通用寄存器满足基本需求

### 3.2 现有指令集不足

#### 3.2.1 函数调用支持不完善
1. **缺少参数传递机制**：CALL指令没有定义参数传递方式
2. **缺少返回值处理**：RET指令没有定义返回值传递方式
3. **缺少栈帧管理**：没有ENTER/LEAVE指令管理函数栈帧

#### 3.2.2 内存访问支持不完善
1. **LEA指令过于简单**：不支持复杂的地址计算
2. **缺少间接寻址**：不支持通过寄存器间接访问内存

#### 3.2.3 类型系统支持不足
1. **缺少类型转换指令**：不支持不同数据类型间的转换
2. **缺少浮点运算**：不支持浮点数运算

### 3.3 建议新增指令

#### 3.3.1 栈帧管理指令
1. **ENTER指令**
   - **功能**：建立函数栈帧
   - **格式**：`enter size, nesting`
   - **示例**：`enter 16, 0`
   - **作用**：为局部变量分配空间，保存旧的基址指针

2. **LEAVE指令**
   - **功能**：清理函数栈帧
   - **格式**：`leave`
   - **示例**：`leave`
   - **作用**：恢复栈指针和基址指针

#### 3.3.2 内存访问增强指令
1. **LOAD指令**
   - **功能**：从内存加载数据到寄存器
   - **格式**：`load reg, [addr]`
   - **示例**：`load R0, [R1+4]`
   - **作用**：支持间接寻址

2. **STORE指令**
   - **功能**：从寄存器存储数据到内存
   - **格式**：`store [addr], reg`
   - **示例**：`store [R1+4], R0`
   - **作用**：支持间接寻址

#### 3.3.3 类型转换指令
1. **CAST指令**
   - **功能**：类型转换
   - **格式**：`cast reg, type`
   - **示例**：`cast R0, int`
   - **作用**：支持不同数据类型间的转换

#### 3.3.4 浮点运算指令
1. **FADD指令**
   - **功能**：浮点加法
   - **格式**：`fadd reg, imm/reg`
   - **示例**：`fadd R0, R1`

2. **FSUB指令**
   - **功能**：浮点减法
   - **格式**：`fsub reg, imm/reg`
   - **示例**：`fsub R0, R1`

3. **FMUL指令**
   - **功能**：浮点乘法
   - **格式**：`fmul reg, imm/reg`
   - **示例**：`fmul R0, R1`

4. **FDIV指令**
   - **功能**：浮点除法
   - **格式**：`fdiv reg, imm/reg`

## 4. 函数调用实现方案

### 4.1 当前问题
1. CALL和RET指令已定义但未实现
2. 缺少参数传递机制
3. 缺少返回值处理
4. 缺少栈帧管理

### 4.2 解决方案

#### 4.2.1 调用约定设计
1. **参数传递**：通过栈传递参数
2. **返回值**：通过AX寄存器返回
3. **调用者清理**：调用者负责清理参数

#### 4.2.2 栈帧布局
```
高地址
+------------------+
|   参数n          |
+------------------+
|   ...            |
+------------------+
|   参数1          |
+------------------+
|   返回地址       |  <- CALL指令压入
+------------------+
|   旧的BP         |  <- ENTER指令压入
+------------------+
|   局部变量1      |  <- BP指向这里
+------------------+
|   ...            |
+------------------+
|   局部变量n      |
+------------------+
低地址
```

#### 4.2.3 指令实现细节

1. **CALL指令实现**：
   ```
   push PC+指令长度  ; 保存返回地址
   jmp 目标地址      ; 跳转到函数
   ```

2. **RET指令实现**：
   ```
   pop PC            ; 恢复返回地址
   ```

3. **ENTER指令实现**：
   ```
   push BP           ; 保存旧的基址指针
   mov BP, SP        ; 设置新的基址指针
   sub SP, size      ; 分配局部变量空间
   ```

4. **LEAVE指令实现**：
   ```
   mov SP, BP        ; 恢复栈指针
   pop BP            ; 恢复基址指针
   ```

### 4.3 实现优先级

#### 4.3.1 高优先级（MVP必须）
1. 实现CALL和RET指令的基本功能
2. 实现ENTER和LEAVE指令
3. 实现参数传递机制

#### 4.3.2 中优先级（第一阶段）
1. 优化函数调用性能
2. 支持可变参数
3. 支持函数指针

#### 4.3.3 低优先级（后续阶段）
1. 支持尾调用优化
2. 支持内联函数
3. 支持异常处理

## 5. 指令编码设计

### 5.1 指令格式
每条指令由以下部分组成：
1. **操作码（Opcode）**：1字节，标识指令类型
2. **操作数（Operands）**：可变长度，根据指令类型而定

### 5.2 操作码分配
```
0x00-0x0F: 内存访问指令
0x10-0x1F: 算术运算指令
0x20-0x2F: 逻辑运算指令
0x30-0x3F: 比较指令
0x40-0x4F: 栈操作指令
0x50-0x5F: 控制流指令
0x60-0x6F: 函数调用指令
0x70-0x7F: 系统调用指令
0x80-0xFF: 保留
```

### 5.3 操作数编码
1. **寄存器操作数**：1字节，0x00-0x07表示R0-R7
2. **立即数操作数**：4字节，32位整数
3. **地址操作数**：4字节，32位地址
