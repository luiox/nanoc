# NanoC 开发计划文档

## 1. 项目概述

### 1.1 项目目标
开发一个完整的C语言子集编译器和虚拟机系统，包括编译器（ncc）、汇编器（nas）和虚拟机（nvm）三个组件。

### 1.2 开发阶段
项目分为三个主要阶段，每个阶段都有明确的目标和交付物。

## 2. MVP（最小可行产品）定义

### 2.1 MVP目标
实现一个能够编译和执行简单C程序的完整工具链。

### 2.2 MVP功能范围

#### 2.2.1 编译器（ncc）MVP功能 ✅ 已完成
1. **基本数据类型**：仅支持`int`类型 ✅
2. **变量操作**：变量声明、赋值 ✅
3. **基本运算**：算术运算（`+`, `-`, `*`, `/`） ✅
4. **控制流**：`if-else`语句、`while`循环 ✅
5. **函数**：简单的函数定义和调用（无参数传递） ✅
6. **I/O**：通过`printf`输出整数 ✅

#### 2.2.2 汇编器（nas）MVP功能 ✅ 已完成
1. **指令支持**：实现核心指令的解析和生成 ✅
   - 内存操作：`lmm` ✅, `st` ✅, `lea` ✅
   - 算术运算：`add` ✅, `sub` ✅, `mul` ✅, `div` ✅, `mod` ✅
   - 位运算：`not` ✅, `and` ✅, `or` ✅, `xor` ✅, `shl` ✅, `shr` ✅
   - 比较指令：`eq` ✅, `ne` ✅, `lt` ✅, `le` ✅, `gt` ✅, `ge` ✅
   - 栈操作：`push` ✅, `pop` ✅
   - 跳转指令：`jmp` ✅, `jic` ✅
   - 函数调用：`call` ✅, `ret` ✅
   - 系统调用：`trap` ✅
2. **标签支持**：支持标签定义和引用 ✅
3. **立即数**：支持十进制和十六进制立即数 ✅
4. **NCO格式**：生成标准NCO字节码文件 ✅

#### 2.2.3 虚拟机（nvm）MVP功能 ✅ 已完成
1. **指令执行**：执行所有MVP支持的指令 ✅
   - 算术运算：`lmm` ✅, `add` ✅, `sub` ✅, `mul` ✅, `div` ✅
   - 比较指令：`eq` ✅, `ne` ✅, `lt` ✅, `le` ✅, `gt` ✅, `ge` ✅
   - 栈操作：`push` ✅, `pop` ✅
   - 跳转指令：`jmp` ✅, `jic` ✅
   - 函数调用：`call` ✅, `ret` ✅
   - 系统调用：`trap` ✅
2. **寄存器**：支持R0-R7寄存器 ✅
3. **栈管理**：支持函数调用栈 ✅
4. **系统调用**：实现基本的I/O和程序退出 ✅
5. **NCO格式**：支持加载NCO字节码文件 ✅

### 2.3 MVP验收标准
1. 能够编译以下示例程序：
```c
int main() {
    int a = 10;
    int b = 20;
    int c = a + b;
    if (c > 25) {
        printf(c);
    }
    return 0;
}
```

2. 能够执行编译后的程序并输出正确结果

## 4. 指令集完善计划

### 4.1 现有指令分析
当前指令集包含27条指令，基本覆盖了栈式虚拟机的核心功能。

### 4.2 需要完善的指令

#### 4.2.1 函数调用相关指令
1. **CALL指令**：
   - 需要支持参数传递
   - 需要支持返回值处理
   - 需要支持调用约定

2. **RET指令**：
   - 需要支持返回值传递
   - 需要支持栈帧清理

#### 4.2.2 内存访问指令
1. **LEA指令**：
   - 需要支持复杂的地址计算
   - 需要支持数组访问

### 4.3 建议新增指令

#### 4.3.1 栈帧管理指令
1. **ENTER指令**：用于函数入口的栈帧建立
2. **LEAVE指令**：用于函数出口的栈帧清理

#### 4.3.2 内存操作指令
1. **LOAD指令**：从内存加载数据到寄存器
2. **STORE指令**：从寄存器存储数据到内存

#### 4.3.3 类型转换指令
1. **CAST指令**：用于类型转换

### 4.4 指令实现优先级

#### 4.4.1 高优先级（MVP必须）
1. 完善CALL和RET指令的实现
2. 完善LEA指令的实现
3. 实现基本的栈帧管理

#### 4.4.2 中优先级（第一阶段）
1. 实现ENTER和LEAVE指令
2. 完善内存访问指令

#### 4.4.3 低优先级（后续阶段）
1. 实现类型转换指令
2. 优化指令集

## 5. 风险管理

### 5.1 技术风险
1. **指令集设计不完善**：可能导致函数调用实现困难
   - 缓解措施：参考成熟的虚拟机设计，如JVM、CLR

2. **编译器实现复杂**：C语言语法复杂
   - 缓解措施：分阶段实现，先实现核心功能

### 5.2 进度风险
1. **开发时间不足**：可能导致功能不完整
   - 缓解措施：严格控制MVP范围，优先实现核心功能

### 5.3 质量风险
1. **测试不充分**：可能导致bug较多
   - 缓解措施：编写充分的测试用例，进行集成测试
